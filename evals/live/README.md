# Live eval suite

These cases run the real skills through `claude plugin eval`. They are the release gate for the
two constraints a per-commit test cannot see: how many questions YOLO asks, and that Accuracy never
sends anything. CI does not run them (they need a Claude login and spend usage); CI runs the
deterministic CLI replays in `tests/replays/` instead. The release workflow refuses to publish a
version that has no passing record in `evals/records/` (see `evals/check_record.py`).

## What each case checks

| Case | Asserts |
| --- | --- |
| `yolo/one-question-per-pass` | the reply ends with exactly one confirmation question (LLM grader), the `scope-scenario` skill fired, `risk-quant-org-setup` never ran |
| `yolo/confirmed-run-to-report` | with the confirmation stated up front: the reply asks nothing more (LLM grader), no org setup, an `rqh report` call, a `report.html` file, and no send-type Bash call |
| `accuracy/no-send-type-calls` | even when asked to send the requests, no mail, `curl` POST or chat-post Bash call; requests were added with `rqh requests add`; the reply shows the drafts and does not claim they were sent (LLM grader) |

## Per-skill cases (`evals/live/skills/<skill>/`)

Each of the eight skills has three cases, and `benchmark-researcher` has one:

| Case | Asserts |
| --- | --- |
| `trigger` | a prompt written for the skill makes it fire (first Skill call; `max_turns: 3`, no Bash) |
| `near-miss` | a prompt written for a sibling skill fires the sibling and not this skill |
| `handoff` | `risk-quant`: `rqh status` runs before the skill it names, and only that skill is invoked; `scope-scenario`, `collect-data`, `simulate`, `report`: the phase runs `rqh status` and invokes no other phase skill; `risk-quant-resume`: `collect-data` runs before any other phase skill for an `awaiting_data` run; `risk-quant-memory`: one yes or no per item, never a blanket question (LLM grader), and no Write or Edit under `.riskquant/library/`; `risk-quant-org-setup`: no send-type Bash call and no Write or Edit but `org-profile.yaml` |
| `benchmark-researcher/behaviour` | no shell, the shipped library hit is returned with its https source, "no usable cited result" rather than an invented range, no `http://` URL in the answer, at most 12 WebSearch and 12 WebFetch calls |

## How the cases see their fixtures

A run starts in an empty workspace and cannot read the repository. `context.add_dirs` does not
help: a `..` path is refused ("escapes the case directory"), and a folder inside the case was
neither copied into the workspace nor shown to the agent. So each case that needs files has a
`case.yaml` with `context.scaffold_script: scaffold.sh`, and the runner passes `--scaffold`. The
scripts are generated by `evals/scaffolds.py` from `evals/replays/<route>/` and
`agents/benchmark-researcher.md` into `example/` (or `agents/`) in the workspace; run
`python evals/scaffolds.py` after changing a fixture, and `tests/skill_evals` fails while a script
is stale. A researcher case runs the agent's instructions in the main agent, because graders may
not see tool calls made inside a subagent.

## Grader rules this suite depends on

Seen on the 0.1.0 smoke run with Claude Code 2.1.308, and pinned in `tests/skill_evals`:

- `tool_used` and `tool_order` match `tool:` as an exact name, not a regex or substring. One
  grader per tool (Write and Edit separately); a pattern there counts nothing, so a `max: 0` guard
  written as a pattern can never fail.
- An eval run does not offer `AskUserQuestion`, even when `allowed_tools` lists it (the session
  starts in dontAsk mode). The skills then ask in text, so question counts are judged on the final
  reply by an `llm` grader.
- In a case with a `case.yaml`, grader keys are validated strictly: `regex` takes `target`, `llm`
  takes `focus`; a wrong key fails the whole case at load.
- Bash, Write and Edit are gated: the runner grants all three, or the run withholds them.
- The default judge for `llm` graders is the small background model. On the 0.1.0 rerun it
  failed a correct one-question reply in 6 of 6 votes, reading its numbered "Confirm, YOLO route"
  choice as a claim that the run was confirmed; sonnet passed it and still failed a second
  question and a false "confirmed" claim. The runner passes `--judge-model sonnet`.
- A `tool_used` guard's `input_match` runs over the call's input as JSON, prose included: a
  script that writes `scenario.yaml` through Bash carries its text ("customer mail is exposed").
  Match a command where it runs, not a word.
- `aggregates.score` is the mean share of graders passed and is what `--threshold` compares;
  `aggregates.passRate` is the share of passing trials, which is what `check_record.py` gates on.

Check that every case loads, for free, with `--max-cost-usd 0` (it reports load errors and
"cannot pass" warnings, then launches nothing):

```
claude plugin eval . --eval-dir evals/live --trust-plugin --scaffold --allow-tools Bash Write Edit \
  --disallow-tools WebSearch WebFetch --ablation none --runs 1 --max-cost-usd 0 --no-publish
```

## Stubbed search, and no connectors

There is no CLI mock for search. The run command disallows `WebSearch` and `WebFetch`, and
`TAVILY_API_KEY` must be unset, so `rqh search` exits 2 and the skills fall back to the shipped
library and assumptions. An eval run also loads no MCP servers (the plugin has none, and the run
uses an isolated config without the host's connectors), so there is no send-type tool to call or
to watch. The no-send gate is the Bash grader plus the LLM grader on the reply, and the CI replays.

## Run it (spends Claude usage; needs the maintainer's go-ahead)

It needs Linux or macOS: a run that grants Bash must confine the shell, and native Windows has no
sandbox backend, so every Bash case is refused there. On Windows, use the container in
`evals/docker/` (its README has the commands). Prerequisites: `pip install -e .` (the cases call
the real `rqh`), `claude` logged in, no `TAVILY_API_KEY`; on Linux also `bubblewrap` and `socat`.

```
python evals/run_live.py --max-cost-usd 35
```

which runs, from the repository root:

```
claude plugin eval . --eval-dir evals/live --trust-plugin --scaffold --allow-tools Bash Write Edit \
  --disallow-tools WebSearch WebFetch --ablation none --runs 3 --concurrency 4 --judge-model sonnet --threshold 0.66 \
  --max-cost-usd 35 --no-publish --json <tmp>/aggregate-result.json
```

and writes `evals/records/<version>.json`: that result plus `plugin_version`, `threshold` and
`suite_sha256` (a hash of every file under `evals/live/` except results, and of `skills/`,
`agents/`, `.claude-plugin/` and `src/rqharness/`). Commit the record, then tag `v<version>`.
Changing any case, grader, skill or package file makes the record stale and the release gate fails.
`check_record.py` requires every case's pass rate to be at least two of three trials.

Cost: 28 cases x 3 trials = 84 runs. A trigger or near-miss run cost 0.16 USD on the smoke run, so
the 16 of them come to about 8 USD; the 9 hand-off and behaviour cases (14 to 30 turns) and the 3
route cases (30 to 60 turns) are the rest, about 15 to 30 USD. `--ablation none` skips the
no-plugin baseline arm, which would double that. Runs take about 1.5 to 2.5 minutes each in the
container, so four at a time (`--concurrency 4`, one shared rate limit) finish in about an hour.
